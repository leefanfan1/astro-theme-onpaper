# 2026-11-07 性能与安全审计

审计对象：dev 分支中的目录交互、文章返回行为、友链管理，以及与这些页面共用的内容渲染、音乐抓取、阅读计数和构建流程。两名独立审查者交叉验证，修复后完成回归。此次审计未发现尚未修复、阻止本次提交的已确认问题；这不代表对所有攻击面或部署环境的完整安全证明。

## 信任边界

文章 Markdown 和内嵌 HTML 由可信站点作者维护。URL 过滤用于阻止危险协议，并非完整 HTML 清洗器；不要将未经信任的访客内容直接接入此渲染链。站点输出为静态文件，阅读计数由 Cloudflare Pages Functions/KV 提供。音乐解析在构建或工具运行时访问外部平台。

## 发现与处理

| 问题 | 影响与前提 | 处理及验证 |
| --- | --- | --- |
| 原始 HTML 在自定义链接过滤之后解析，实体编码和控制字符也可能绕过协议检测 | 恶意内容混入可信作者文章时，可留下可执行链接；浏览器执行还受部署 CSP 等条件影响 | 过滤前先解析 HTML，按浏览器规则处理 TAB/LF/CR 与前导控制字符；同时检查 HTML href 和 SVG xLinkHref。覆盖普通、实体编码及 SVG 攻击样例；保留安全 SVG 和字面代码示例 |
| 音乐抓取自动跟随重定向，未约束每一跳目的地 | 允许的平台若产生攻击者可控重定向，构建机器可能访问非预期地址 | 每次请求和每一跳都只允许指定 HTTPS 主机，拒绝凭据和非默认端口，最多五次重定向。受控本地传输复现并验证拦截；未证实真实音乐平台存在可利用开放重定向 |
| 外部音乐响应无大小上限 | 异常上游可能消耗构建机器内存 | 对声明长度和实际流字节数实施 5 MiB 上限，超限取消读取；验证分块流、声明超限及正常响应 |
| 友链 URL 校验和空行处理不足 | 危险协议或多组空白可能造成错误链接或条目解析异常 | 仅允许 HTTP(S)，使用标准 URL 解析并输出规范地址；覆盖 CRLF、多空行、NBSP、缺省简介和六个原有条目 |
| 目录自动跟随可能把键盘焦点项滚出可见区域 | 键盘阅读和导航受影响 | 焦点在目录内时暂停自动跟随，取消边缘遮罩；验证键盘、悬停反转、减少动态效果及页面切换清理 |

同时复核了动态内容转义、外链 rel 属性、阅读计数接口的参数/方法校验、跨站写入拒绝、缺失 KV 时的受控错误、公开响应头配置和仓库中的敏感凭据模式。

## 回归结果

- npm test：22 项通过，0 失败。覆盖友链解析、HTML/SVG URL 过滤、音乐响应转义、抓取边界和阅读计数。
- SVG 独立浏览器复核：Chromium 156 实际点击 12 个经过渲染的攻击样例，全部不执行；未过滤的阳性对照可执行，安全 SVG 图形和锚点跳转保持正常。
- npm run build：成功，生成 19 个页面。
- npm audit：已知依赖漏洞为 0（info/low/moderate/high/critical 均为 0）；仅反映检查时漏洞库收录的结果。
- npm ls --depth=0：依赖树正常。
- npm run shots：15 个桌面/移动端、明暗主题截图与交互场景通过，未发现页面运行异常或横向溢出。
- 构建产物检查：545 处本地 href/src 均可解析，六张友链卡片保留；目录压力测试草稿未进入生产 HTML、RSS、搜索索引和站点地图。
- 手动浏览器交互：来源页滚动后进入文章，连续点击三个章节不增加历史条目，点击返回可回到来源页并恢复滚动位置。
- 首页 axe 检查：0 项违规，1 项待人工判断的隐藏对话框引用检查；未据此宣称全部页面完全符合无障碍标准。

目录仅在存在被隐藏子标题或实际文字截断时启用展开，保持正文原有布局；用透明度过渡隔开文字重排，不逐帧改变文字宽度。压力测试文章保留为 draft，供开发复现长目录问题。

本地生产预览，Lighthouse 13.6.0，Playwright Chromium。以下为实验室单次测量，移动端采用默认模拟节流；不能替代线上真实用户指标。

| 页面 / 模式 | 性能分 | LCP | TBT | CLS | 无障碍 / SEO |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首页 / 移动 | 88 | 1.394 s | 457 ms | 0 | 100 / 100 |
| Markdown 指南 / 移动 | 92 | 1.897 s | 294.5 ms | 0 | 100 / 100 |
| 友链 / 移动 | 100 | 1.394 s | 0 ms | 0 | 100 / 100 |
| Markdown 指南 / 桌面 | 96 | 0.454 s | 160.6 ms | 0 | 100 / 100 |

移动端首页的主线程工作仍有优化空间。文章移动端前一次测量为 79 分，最终复测为 92 分，说明单次测量存在波动；没有为提高分数改动网站布局或字体策略。此次未取得可代表线上用户的 INP 数据。

本机 Kaspersky 会注入外部 HTTP 脚本，显著干扰初次结果。表中测量仅通过 Lighthouse 请求过滤屏蔽其注入域名，未更改系统防护设置。注入请求的 HTTPS 检查以及静态预览下 /api/views 的 404 仍影响最佳实践分：首页和友链 81、文章 77，不能直接解释成线上站点漏洞。

原始 Lighthouse JSON、依赖审计 JSON 和截图保留在本机被 Git 忽略的 _analysis/ 与 screenshots/ 中，不作为线上产物。

## 部署验证边界

本地 Astro 静态预览不应用 Cloudflare 的 public/_headers，也不运行 Pages Functions。已审阅头配置并用模拟 KV 测试接口，但未实际验证线上 HTTPS、CSP、KV 绑定、配额或 WAF。

匿名阅读计数允许直接 HTTP 客户端调用；浏览器跨站限制不构成防刷机制。若需要控制恶意刷量，应在部署侧配置 Cloudflare 限速/WAF。此次未接入部署账户，也未进行线上压测。
